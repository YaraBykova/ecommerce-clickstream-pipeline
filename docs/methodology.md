# Методика и подробные результаты

Результаты проверены 2026-11-19 на полном исходном архиве за период
с 2020-09-24 по 2021-02-28.

## Путь данных

```text
CSV / ZIP → Python → raw → core → mart → графики
```

- `raw.events_import` хранит типизированные события, источник и время загрузки.
- `raw.import_batches` хранит ID доставки, контрольную сумму и состояние обработки.
- `core` содержит связанные таблицы пользователей, товаров, сессий и событий.
- `mart` содержит представления воронки, категорий и покрытия данных.

Изменения raw, журнала партии и core применяются одной транзакцией.
Ошибка откатывает эти изменения. Параллельные загрузки и полная пересборка
используют общую блокировку PostgreSQL.

## Идентичность доставки

В источнике отсутствует отдельный ID события. Доставка определяется парой
**ID партии + номер записи**. Одинаковые записи внутри партии сохраняются
как самостоятельные события.

По умолчанию ID вычисляется как SHA-256 нормализованных значений записей
в исходном порядке. Имя файла и упаковка ZIP в расчёт суммы не входят.
Переименование CSV и переупаковка сохраняют ID. Его можно задать явно
аргументом `--batch-id`.

Повтор ID с тем же содержимым даёт 0 новых строк. Изменение содержимого
под прежним ID вызывает ошибку. Разные явные ID означают разные доставки.
Для устранения повторов между перекрывающимися партиями нужен ID события
от источника. Полный архив и его нарезка проверяются в отдельных базах.

## Поздние события

Порядок действий определяется временем события, независимо от порядка доставки.
После поступления партии пересчитываются её сессии по всем их событиям в raw,
а также границы связанных пользователей и товаров.

| Поступление | Время действий | Этап воронки |
|---|---|---|
| Первая партия | Просмотр в 10:00, покупка в 10:10 | Просмотр |
| Поздняя партия | Корзина в 10:05 | Покупка |
| Повтор поздней партии | Те же записи | Покупка, 0 новых строк |

Позднее событие может нарушить правила сессии. В таком случае её прежние
события исключаются из core, связанные сущности пересчитываются.
История событий сохраняется в raw.

## Отбор сессий

Сессия берётся из поля `user_session` источника. В core включаются сессии
с заполненным ID, одним пользователем и длительностью до 24 часов включительно.
Сессии из одного события сохраняются.

| Показатель | Количество |
|---|---:|
| События raw | 885 129 |
| События core | 806 078 |
| Исключённые события | 79 051 |
| Пользователи core | 400 263 |
| Товары core | 52 608 |
| Сессии core | 479 958 |

| Причина исключения | События |
|---|---:|
| Отсутствует ID сессии | 165 |
| В сессии несколько пользователей | 1 527 |
| Длительность превышает 24 часа | 78 578 |

Причины пересекаются, поэтому их количества не складываются в общий итог.
Порог 24 часа выбран для проекта и влияет на состав анализируемых сессий.

## Общая воронка

Для каждой принятой сессии определяются первый просмотр, первая корзина
строго после него и первая покупка строго после этой корзины.
Товары на разных шагах могут различаться.

| Этап | Сессии |
|---|---:|
| Просмотр | 477 930 |
| Корзина после просмотра | 38 488 |
| Покупка после корзины | 19 065 |

Просмотр → корзина составляет 8,05%, корзина → покупка — 49,53%,
просмотр → покупка — 3,99%. Общая конверсия рассчитана от сессий с просмотром.
Каждая сессия учитывается на шаге один раз.

Поле `funnel_stage` принимает значения `view`, `cart`, `purchase` или `no_view`.
События с одинаковым временем не образуют переход, поскольку требуется
строгое увеличение времени. Для покупки нужен весь предшествующий порядок действий.

## Воронка по категориям

Единица расчёта — пара `session_id + category_code` с просмотром.
Разные `category_id` с одинаковым заполненным названием объединяются внутри
сессии. Пробелы по краям названия удаляются.

Берётся первый просмотр категории и первая последующая корзина той же
категории. Товары могут различаться. Повторные действия дают один переход.
Сессия с просмотрами двух категорий участвует в обеих.

| События одной сессии | Результат |
|---|---|
| Просмотр A → корзина B | У A просмотр без перехода. B учитывается при наличии собственного просмотра |
| Просмотр A → просмотр B → корзина B | У A просмотр без перехода, у B переход |
| Просмотр A → просмотр A → корзина A → корзина A | Одна пара и один переход у A |
| Просмотр A и корзина A в одно время | Требуется более поздняя корзина |

В 107 известных категориях получено 344 777 просмотровых пар и 32 571 переход
к корзине — 9,45%. Единица расчёта и покрытие отличаются от общей воронки,
поэтому суммы по категориям не равны числу уникальных сессий магазина.

Для списка кандидатов отбираются категории с минимум 1000 просмотровых
сессий и конверсией ниже 9,45%. Они сортируются по числу сессий без корзины.
Это описательный способ выбрать крупные группы для дальнейшей проверки.
Статистическая значимость различий отдельно не оценивалась.

| Категория | Сессии с просмотром | Дошли до корзины | Без перехода | Конверсия |
|---|---:|---:|---:|---:|
| Телефоны | 49 264 | 4 261 | 45 003 | 8,65% |
| Картриджи | 23 684 | 2 215 | 21 469 | 9,35% |
| Акустика | 15 733 | 900 | 14 833 | 5,72% |
| Ноутбуки | 15 154 | 1 292 | 13 862 | 8,53% |
| Телевизоры | 11 972 | 481 | 11 491 | 4,02% |

## Покрытие названиями

| Название категории | События core | Доля |
|---|---:|---:|
| Заполнено | 587 072 | 72,83% |
| Отсутствует | 219 006 | 27,17% |

Эти доли рассчитаны по событиям всех типов после отбора сессий.
Сравнение категорий относится к именованной части данных.
События с неизвестной категорией участвуют в общей воронке.
Проверка восстановления названий по другим событиям того же товара или
ID категории дала ноль восстановлений. Нужен дополнительный справочник.

Для исследования причин различий конверсии потребуются дополнительные данные
о товарах, наличии и работе магазина. Наблюдаемые показатели относятся
к событиям отобранных сессий указанного исторического периода.
