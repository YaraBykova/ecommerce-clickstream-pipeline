# Проверка партий и поздних событий

Проверено 2026-11-19 на PostgreSQL 15. Использован полный исходный архив
`events.csv.zip` с 885 129 событиями. Проверка выполнялась в отдельной
временной базе. Исходный архив использовался для чтения.

## Результаты полного прогона

Архив разделён на девять CSV-партий — восемь по 100 000 строк
и последняя на 85 129 строк. После каждой доставки пересчитывались
затронутые сессии и связанные с ними пользователи и товары.

| Проверка | Результат |
|---|---:|
| События raw после девяти партий | 885 129 |
| События core | 806 078 |
| Сессии core | 479 958 |
| Зарегистрированные партии | 9 |
| Партии, ожидающие обработки core | 0 |
| Новые строки при повторной доставке всех партий | 0 |
| Пересчитанные сессии при повторной доставке | 0 |
| Расхождения с полной пересборкой | 0 |

После повторной доставки журнал партий остался тем же, включая время
регистрации и применения к core. Воронка дала 477 930 сессий с просмотром,
38 488 с последующей корзиной и 19 065 с покупкой после корзины.

## Что сверялось с полной пересборкой

Сначала сохранены снимки всех колонок девяти таблиц и представлений.
Затем выполнен `02_build_core.sql` по тому же raw. В обе стороны
проверено различие через `EXCEPT ALL`, которое учитывает кратность строк.
Во всех объектах число различий равно нулю.

- `core.users`, `core.products`, `core.sessions`, `core.events`.
- `mart.session_funnel`, `mart.funnel_summary`.
- `mart.session_category_funnel`, `mart.category_conversion`.
- `mart.category_data_quality`.

В 107 известных категориях подтверждены 344 777 просмотровых пар
и 32 571 переход к корзине. Контрольные запросы `05_check_marts.sql`
и `07_check_category_conversion.sql` вернули нули по всем несоответствиям.
Графики пересозданы по проверенным витринам.

## Проверка с чистой установки

Проект дополнительно выгружен из Git без локального окружения и настроек.
В новом окружении установлены зависимости из `requirements.txt`, запущен
отдельный PostgreSQL 15. Все 21 тест прошли.

Обычными командами из инструкции полный архив и девять партий загружены
в две независимые базы. Повторы дали 0 новых строк. Построчное сравнение
всех колонок девяти таблиц и представлений подтвердило их совпадение.
Пересозданные графики побайтово совпали с изображениями в репозитории.

Проверены Python 3.14.6, psycopg 3.3.9, Matplotlib 3.11.2 и NumPy 2.5.5.

## Перенос старой загрузки

В изолированной базе воспроизведена прежняя схема raw без метаданных партий.
Полный архив передан обычному `run_pipeline.py`. После построчной сверки
зарегистрированы все 885 129 прежних строк; число новых вставок равно нулю.
Сохранены их ID. Все девять таблиц и представлений повторно совпали со снимками.

Если прежние строки отличаются от переданного источника, регистрация
завершается ошибкой с откатом. Это предотвращает смешение старой загрузки
с новой доставкой при отсутствии сведений об идентичности прежних строк.

## Интеграционные тесты

[21 тест](../tests/test_batches.py) прошёл на настоящем PostgreSQL.
Каждый тест создаёт и удаляет отдельную базу.

Проверки охватывают позднюю корзину между просмотром и покупкой,
повторную доставку, изменённое содержимое под прежним ID, одинаковые действия,
переупаковку ZIP, ошибки CSV и цены, откат при ошибке core,
параллельную доставку, превышение длительности сессии, появление второго
пользователя, перенос прежних данных, разделение файла и запуск через CLI.
Отдельно проверено, что незатронутая сессия сохраняет прежнюю версию строки.

## Граница гарантии повторной доставки

Идентичность определяется ID партии и номером записи. Одинаковые строки
внутри партии сохраняются. Разные явно заданные ID обозначают разные
доставки. Для устранения повторов между перекрывающимися партиями нужен
стабильный ID события от источника.

Команды запуска и настройки приведены в [инструкции](../docs/setup.md).
